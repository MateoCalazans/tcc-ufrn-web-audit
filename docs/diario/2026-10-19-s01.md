## Decisões tomadas
- **Nenhuma exige ADR novo.** Registradas aqui por transparência:
  - O campo `chromium` reporta a versão do **Chromium que o Playwright usa**, lida de `playwright-core/browsers.json` (o `require` de subpath é bloqueado pelo `exports`, então o arquivo é resolvido pelo caminho do módulo). É esse o navegador que renderiza DOM/screenshot/HAR na coleta, então é o que precisa ser reproduzido — mais relevante que um Chromium de sistema (que fica como fallback no PATH).
  - **Congelamento de versões:** o stack foi instalado e registrado nesta sessão para fixar as versões **antes** da coleta. Vale a regra do README de `docs/ambiente/`: não atualizar Chrome 155 / Chromium 156 / Lighthouse 13.5 / Node 24 entre a coleta (S08) e a validação (S18); se inevitável, registrar aqui e no diário.
  - Detecção de versões via `spawnSync` com a linha como **string única** (`shell: true`) para evitar o aviso `DEP0190` do Windows ao passar `args` com `shell`; só comandos constantes do próprio script chegam lá (sem entrada externa).
  - O bloco `meta.toolVersions` (padrão da regra 10, via `src/shared/meta.ts`) segue com node/lighthouse/playwright; o bloco `tools` do ambiente é mais rico (inclui npm, chrome, chromium, java). Redundância proposital nos três que aparecem em ambos.
