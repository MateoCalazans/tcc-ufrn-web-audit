# 2026-11-16 — S16: LLM para landmarks

**Objetivo:** Acrescentar ao módulo 3 a regra `landmarks-llm`: um LLM propõe qual `<div>` vira `header`/`nav`/`main`/`footer` quando o landmark falta, com prompt versionado, saída JSON, validação do resultado e registro de tokens e custo.
**Ferramenta:** Claude Code (Opus 5.5); modelo do sistema avaliado: Claude Haiku 5.5 · **Duração:** ~2,9h, de ~11:42 a ~14:35 de 2026-11-16.

- Os commits são de 14:33–14:34 (`git log --format="%h %ad" --date=format:%H:%M`). O fechamento foi às 14:35 (`date`).

## Resultados (números vêm de scripts, com comando)
- `node node_modules/vitest/vitest.mjs run` → 37 arquivos, **352 testes** passando (eram 327 na S15). `npx tsc --noEmit -p .` sem erros.
- Amostra: 29 elegíveis (conjunto principal, `status_semantica == "ok"`, sem stub de meta refresh, soma dos landmarks = 0). Sorteio com `sample(n=5, random_state=16)`: `ecaan1.ect`, `gpc.ect`, `lar.ect`, `erros.si` e `quimica`.
- Estimativa de custo, sem chamar a API (`npx tsx <scratchpad>/estimar.ts`, script fora do repo; supõe 3,5 caracteres por token e 800 de saída):
  - 107 dos 240 sites com HTML chamariam o modelo;
  - estimativa de US$ 0,06 para o corpus inteiro; pior caso de US$ 0,24.
- `npm run recommend -- --site ... --llm`, em 3 rodadas, registradas em `data/processed/llm-runs.csv` (13 linhas):
  - `ecaan1.ect` e `erros.si` sem chamada: "nenhum `<div>` candidato" (listagem do Apache e SPA Angular);
  - nas chamadas: 1192–1759 tokens de entrada, 325–1142 de saída, US$ 0,0003–0,0007 por site, todas em `end_turn`, sem proposta rejeitada;
  - **gasto total: US$ 0,003786** (`gastoRegistrado("data/processed/llm-runs.csv")`).
- `npx tsx scripts/landmarks-validacao.ts --site ...`, 1ª rodada (sem a checagem de CSS):
  - texto igual e o mesmo número de erros do vnu antes e depois (gpc 1, lar 1, quimica 16);
  - screenshots servidos do HAR: `lar.ect` com 0 pixel diferente; `quimica` com 0,063%, contra 0,052% de ruído; **`gpc.ect` com 1,56%, contra 0% de ruído**. O CSS `div#content { width: 940px; … }` deixou de valer, e o subtítulo mudou de lugar.
- 3ª rodada (com a checagem de CSS):
  - `gpc.ect` ficou só como recomendação (`CSS depende da tag: div#content`);
  - `lar.ect` com 0 pixel diferente; `quimica` com 0,054%, contra 0,051% de ruído; texto e vnu iguais.
  - No `quimica`, o modelo propôs `.logo` → `header` e `.site-info` → `main`; na 1ª rodada tinha sido `.comming-soon` → `main`.

## Decisões tomadas
- **Haiku 5.5, sem temperatura 0, esqueleto de candidatos em vez do HTML, identificadores `cN` em vez de seletor CSS, troca automática condicionada à verificação.** ADR: [016](../decisoes/016-llm-para-landmarks.md) (proposto).
- **Teto de gasto acumulado de US$ 4,50** (crédito de US$ 5 do autor) e **checagem de CSS antes da troca**: registrados no ADR 016 (decisões 5 e 6 e seção "Resultados da amostra").
- **Rodada da validação de antes da checagem de CSS mantida.** As linhas da 1ª e da 2ª rodada continuam no `llm-runs.csv` como evidência do caso que motivou a checagem. Decisão do Claude, citada no ADR.
- **Interface visual (Fase 7, S20–S21)** fica para depois da S19, fora do congelamento da `v1.0`. O ADR 017 está previsto no roteiro e não foi escrito.

## Problemas / dúvidas para o orientador
- Validar o [ADR 016](../decisoes/016-llm-para-landmarks.md) (proposto).
  - Sem temperatura 0, a mesma entrada dá propostas diferentes (o `quimica` mudou entre as rodadas). A reprodutibilidade fica sendo a do registro.
  - A qualidade da escolha não foi medida, porque exigiria rotulagem manual.
- **`git_commit` das linhas do `llm-runs.csv`.** As 13 linhas registram `ea5af13`, porque o código foi executado antes de ser commitado (`d9164c9`). O SHA-256 do prompt (`b19e8d1c…`) identifica o prompt. O código da 3ª rodada é o do `d9164c9`. Rodar de novo custaria cerca de US$ 0,001, mas o autor não escolheu entre rodar e anotar, e o Claude seguiu anotando.
- **Cobertura da regra.** Ela age no HTML bruto, então SPA e listagens ficam de fora (2 de 5 na amostra). Pela estimativa, só 107 de 240 sites teriam candidato, contra 73,7% do conjunto principal com algum landmark ausente no DOM renderizado.
- **Limites da checagem de CSS.** Ela não segue `@import` e não vê CSS injetado por script, atributos `style` ou scripts que selecionem `div`.
- **Referências do ADR 016 citadas de memória:** HTML-AAM; WCAG 1.3.1 / ARIA11; eMAG 1.5.
- **Chave da API em `.env` (ignorado pelo git).** Apagar a chave no Console ao fim do projeto.
